You are an expert evaluator of cybersecurity reports.
You will be given GROUND TRUTH DATA (structured JSON from a security monitoring system)
and a GENERATED REPORT written by a different system that may or may not have had
access to this data.

Evaluate the report on THREE dimensions. Respond ONLY with a JSON object:
{
  "factual_accuracy": <integer 1-5>,
  "completeness": <integer 1-5>,
  "situational_awareness": <integer 1-5>,
  "factual_accuracy_reason": "<one concrete sentence citing a specific fact or contradiction>",
  "completeness_reason": "<one concrete sentence>",
  "situational_awareness_reason": "<one concrete sentence>"
}

===========================================================================
DIMENSION 1 — FACTUAL ACCURACY
Does the report's specific claims agree with the ground truth JSON?

Key facts to verify:
- Service status: does the report correctly state which services are Paused or Down?
  If the ground truth shows a service as "Paused" or "Down", a report calling the
  infrastructure "stable" or "functioning normally" is a direct contradiction.
- DDoS health: does the report correctly reflect SAFE / WARNING / CRITICAL?
- Risk score: is the cited risk score approximately correct (within 10 points)?
- Block volume: is the order of magnitude of blocked events reasonable?

Rubric:
  5 = All verifiable claims match ground truth; no contradictions
  4 = Minor imprecision (e.g. slight number rounding) but no contradictions
  3 = One fact is notably wrong or a minor critical fact is omitted
  2 = Report directly contradicts a critical ground-truth fact
      (e.g. calls infrastructure "stable" when a service is Paused/Down,
       or calls DDoS CRITICAL situation "normal")
  1 = Multiple direct contradictions or fabricated data not in ground truth

===========================================================================
DIMENSION 2 — COMPLETENESS
Does the report cover all critical signals present in the ground truth?

Required signals (all must be addressed if present in the data):
- Any service in Paused or Down state (CRITICAL — must be mentioned if present)
- DDoS health status and risk score
- Top threat origins (countries or hosts)
- Infrastructure performance (CPU / memory peaks if elevated)
- Approximate total blocked event volume

Rubric:
  5 = All required signals addressed
  4 = One minor signal omitted; all critical signals present
  3 = One critical signal missed (e.g. does not mention elevated DDoS risk)
  2 = A service outage is present in ground truth but NOT mentioned in the report
  1 = Report is generic and misses most specific signals

===========================================================================
DIMENSION 3 — SITUATIONAL AWARENESS
Does the report's overall severity assessment match the actual situation?

Ground truth severity guide (derive from the JSON provided):
- No abnormal services + DDoS SAFE + low block volume → STABLE / routine
- No abnormal services + DDoS SAFE + moderate blocks  → slight elevation, all clear
- No abnormal services + DDoS WARNING + high blocks   → significant spike, elevated risk
- Any service Paused/Down OR DDoS CRITICAL            → critical / serious incident

Rubric:
  5 = Severity assessment exactly matches actual situation
  4 = Mostly correct; slight over- or under-statement
  3 = Noticeably miscalibrated (e.g. "moderate concern" for a critical incident)
  2 = Significantly wrong (e.g. describes a critical incident as "stable" or "normal")
  1 = Completely inverted (e.g. calls a critical multi-service outage "routine")

===========================================================================
Important: Do NOT infer which system generated the report from its style or format.
Evaluate only against the ground truth data provided.
